1. The authenticated seller registers an instruction-only skill with public metadata, compatibility requirements, price, purchase licence, and evaluation policy. FastAPI validates the allowed content, applies size and structure limits, and creates an immutable version with a content hash. Private skill instructions are accessible only to authorized evaluation and delivery components, and paid checkout is enabled only after the seller’s payment association is validated.
2. AgentGain generates a public product link for the seller’s “Test, then buy” button. Opening the link creates a buyer-specific checkout session. The backend resolves the authoritative seller, skill version, price, and evaluation policy, displays them to the buyer, and later freezes them in the approved contract. Checkout details and status are protected by buyer and seller access controls.
3. The buyer’s supported agent attempts the original task, and AgentGain records its input, output, configuration, and either a validated failure or buyer-reported concern. The failure identifies a possible need for assistance but is not used as proof that a paid skill is valuable. Where AgentGain reproduces the agent in its own environment, that limitation is shown explicitly.
4. AgentGain filters available skills using verified compatibility metadata, then uses the buyer assistant to explain relevant candidates and their seller-stated claims. Recommendations do not authorize purchases or establish improvement. The buyer opens the selected checkout, while a suitable free or simple comparison workflow is identified independently for the evaluation contract.
5. The buyer supplies a separate, permitted evaluation dataset and the configuration of a supported agent. AgentGain validates records and labels, checks duplication and evaluation feasibility, and separates model inputs from verifier-only answers. Evaluation runs on an AgentGain-controlled host under disclosed privacy and retention terms, so the private paid package is not delivered to the buyer before payment.
6. AgentGain prepares a versioned contract specifying the paid skill, existing workflow, credible alternative, evaluation data, agent configurations, grading rules, statistical method, economic assumptions, total cost treatment, buyer surplus requirement, and payment policy. The buyer explicitly approves automatic capture on a qualifying result under the seller’s agreed evaluation terms. The backend freezes the contract before any paid evaluation begins.
7. The backend creates a PayPal order with AUTHORIZE intent using the frozen contract amount, currency, and receiving merchant. After buyer approval through SDK v6, the backend authorizes the order, validates and records the authorization resource, and confirms that sufficient evaluation time remains. The interface shows an authorized payment hold, not a completed purchase.
8. After confirmed authorization, AgentGain records a durable, uniquely identified evaluation job. A restricted Python worker claims it using a renewable lease, verifies the frozen contract and package, and executes within the agreed deadline and resource budget. Checkpoints and lease validation allow crash recovery without accepting duplicate or stale results.
9. AgentGain executes the buyer’s frozen existing workflow and a preselected credible free or simple alternative on the evaluation records. It records outputs, failures, configuration identifiers, token usage, and timing for every scheduled run. Comparator selection is completed before final evaluation, and no comparison arm receives another arm’s outputs.
10. The worker runs the exact paid skill within the frozen agent configuration on the same evaluation records as the comparison arms. A balanced schedule controls execution-order effects, task information is preserved, and all skill-related resource overhead is recorded. Fresh contexts and restricted runtime permissions prevent access to expected answers, payment systems, and unauthorized tools.
11. An independent, versioned Python verifier grades every scheduled output using frozen task rules, compares the paid capability with both approved alternatives, and calculates economic benefit, uncertainty, costs, and critical regressions. It produces a reproducible PASS, FAIL, INCONCLUSIVE, or TECHNICAL ERROR decision with supporting evidence. Only a qualifying decision can make the checkout eligible for capture.
12. The buyer evidence screen presents the existing workflow, free alternative, and paid capability side by side, with graded outcomes, regressions, resource use, economic assumptions, and uncertainty. It explains the frozen decision and separately shows payment progress. Private package content and sensitive execution logs are excluded, and payment processing continues independently of whether the page remains open.
13. The payment controller validates the final evaluation decision, frozen contract, authorization, merchant, amount, currency, and deadline before attempting capture. Non-qualifying or unresolved evaluations follow the approved void policy. Capture and void are serialized, operation identifiers survive retries, and uncertain outcomes are reconciled before further action. Already captured payments use the separate refund process when applicable.
14. Payment verification and recovery run continuously across the purchase lifecycle. Verified, deduplicated webhooks and authenticated API responses feed one guarded payment state machine. Persistent operation records support safe retries and reconciliation, while unresolved states remain pending or require operational review. Refunds, reversals, and delivery failures are tracked without rewriting the original evaluation result.
15. After a matching PayPal capture is confirmed as COMPLETED, AgentGain creates a unique buyer entitlement and a durable delivery task. The delivery process verifies the package hash and provides authenticated access to the exact tested version and licence. A receipt links the contract, comparison evidence, configuration scope, and payment reference. Delivery retries never initiate another charge.
16. The buyer’s agent verifies the purchased package and its compatibility before retrying the original task. AgentGain records the actual result, remaining errors, resource use, and any configuration differences. Post-purchase execution remains separate from the evidence used to authorize capture, and consequential business actions remain subject to the buyer’s existing permissions.
17. AgentGain records deduplicated checkout, authorization, evaluation, capture, delivery, refund, and reuse events with precise definitions. Seller views distinguish gross payments, applicable deductions, evaluation costs, observed task outcomes, and buyer feedback. Sandbox activity is visibly separated from live commerce, and no metric is presented as incremental PayPal revenue without supporting commercial evidence.
